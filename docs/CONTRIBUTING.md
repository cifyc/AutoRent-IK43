# Робота в команді AutoRent (ІК-43)

## Розподіл відповідальності

- Смакота Іван: React + TypeScript, UI/UX, каталог, клієнтські сценарії.
- Перець Єгор: Python, Django REST Framework, PostgreSQL, бізнес-правила, серверні тести.
- Разом: вимоги, уточнення рішень, документація, код-рев’ю й інтеграція.

Це **план розподілу відповідальності**, а не свідчення того, хто саме створив наявні технічні коміти.

## Правила Git

1. Не додавати код напряму до `main`, якщо він має пройти спільний перегляд.
2. Створити власну гілку `feature/<коротка-назва>` для кожної задачі.
3. Коміти мають пояснювати конкретну зміну (`feat:`, `fix:`, `test:`, `docs:`).
4. Перевірити тести та створити Pull Request у `main`.
5. Запросити напарника на Review; не позначати чужі коміти як свої.
6. Зливати лише після перевірки коду та успішних тестів.

## Тести

```bash
python -m pip install -r requirements-test.txt
python -m unittest discover -s tests -v
```

У Windows додатково потрібна база часових поясів `tzdata`, яка встановлюється через `requirements-test.txt`.

## Прийняття Pull Request

У PR мають бути опис мети, список змінених файлів, результати тестів і рев’ю другого учасника. Для викладача можна показати **Commit history**, **Pull requests**, **Reviews** і **Actions** з фактичними статусами, не імітуючи виконання.
