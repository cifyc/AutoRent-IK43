# Відображення принципів SOLID у каркасі

| Принцип | Демонстрація | Зауваження |
|---|---|---|
| **S** — Single Responsibility | `PricingPolicy` рахує вартість; `CarViewSet` віддає каталог; `BookingService` координує операції бронювання. | У реальній системі сервіси можна розділити ще дрібніше. |
| **O** — Open/Closed | `BookingService` приймає стратегію `pricing_policy`; можна додати іншу стратегію ціни без зміни сценарію бронювання. | Складні тарифні правила ще не реалізовані. |
| **L** — Liskov Substitution | Стратегії, що мають однаковий контракт методу `quote(...)`, можна підставляти замість `PricingPolicy` без зміни клієнтського коду. | Поведінкові контракти потребуватимуть окремих тестів. |
| **I** — Interface Segregation | Інтерфейси читання каталогу та операцій над бронюванням рознесені в окремі viewset; браузер каталогу не залежить від методів менеджера. | Додаткові API варто деталізувати окремо. |
| **D** — Dependency Inversion | `BookingService` отримує `pricing_policy` через конструктор замість жорстко зафіксованої реалізації ціноутворення. | Доступ до Django ORM досі є конкретною залежністю; повний DIP для репозиторію — наступний етап. |

Таблиця показує **приклади застосування**, а не заяву, що всі принципи дотримані вичерпно.
